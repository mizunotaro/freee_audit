## 0. Executive Summary

LOG-002 audited the **Class-A API route groups** — `audit`, `auth`, `conversion`, `debt`,
`deferred-accrual`, `freee`, `journal-proposal`, `journals`, `kpi`, `tax`, `valuation` — to
determine which **mutating handlers** (POST / PUT / PATCH / DELETE, plus the credential/sync
side-effects reached via GET) write a row to the tamper-evident `AuditLog` chain.

Two structural problems were found. Both are `PENDING HUMAN DETERMINATION`.

### 0.1 Central finding — the integrity chain is bypassed everywhere it is used

The platform's audit log is a **blockchain-style integrity chain**
(`src/lib/audit/audit-logger.ts`). The correct writer is `auditLogger.log(...)`, which:

1. reads the previous entry's `contentHash` (`getPreviousHash`, line 81),
2. computes an HMAC-SHA256 `contentHash` over the entry (`computeEntryHash`, line 40),
3. persists both `previousHash` and `contentHash` (`prisma.auditLog.create`, line 115).

Integrity is later verified by `auditLogger.verifyIntegrity()` (line 284), which recomputes
each hash and compares.

**The defect:** every Class-A route that logs at all writes **directly** via
`prisma.auditLog.create({ ... })`, omitting both `contentHash` and `previousHash`. Because the
Prisma model declares both columns **nullable** (`prisma/schema.prisma:180-181`), these inserts
succeed — but they produce rows whose hash is `null` and which do not link to the chain.
Consequences (`PENDING HUMAN DETERMINATION` on severity):

- Each such row is reported as a **broken entry** by `verifyIntegrity()` (`null !== expectedHash`).
- Because `getPreviousHash()` returns the *most recent* row's `contentHash`, a direct-written
  `null` hash becomes the `previousHash` of the **next** legitimately-logged entry, propagating
  chain corruption forward until the next gap.

### 0.2 Second finding — most mutating handlers log nothing at all

Outside the 6 direct-write sites in §0.1, **no Class-A mutating handler writes the security
audit log**. The auth wrappers (`withAuth`, `withAccountantAuth`, `withAdminAuth`,
`withRateLimit`) were verified to contain no audit logging, so routes are not covered
centrally. CRUD on conversion projects/COAs/mappings, tax settings/schedules/payments, KPI
definitions, deferred/accrual expenses, freee token storage & data sync, journal-proposal
create/analyze/upload, and valuation QA are all unlogged.

### 0.3 Coverage at a glance (`PENDING HUMAN DETERMINATION`)

| Status | Meaning | Class-A handlers |
|--------|---------|------------------|
| **PARTIAL** | Writes `AuditLog` but via direct `prisma.auditLog.create` — chain bypass (§0.1) | 6 |
| **MISSING** | Mutating handler, no audit-log write of any kind | ~38 |
| **PRESENT** | Uses `auditLogger.log(...)` correctly | **0** |

The only correct (`auditLogger.*`) writers in the entire `src/` tree live outside Class-A:
`src/services/investor/invitation-service.ts`, `src/app/api/investor/access-log/route.ts`,
`src/jobs/audit-job.ts`, `src/jobs/journal-sync.ts`. (The same direct-write anti-pattern also
appears out-of-scope at `src/app/api/settings/api-keys/[provider]/route.ts:125,175`.)

## 2. How a correct audit-log write should look

Reference writer (`src/lib/audit/audit-logger.ts:90`):

```ts
export interface AuditLogInput {
  userId?: string
  action: string
  resource: string
  resourceId?: string
  ipAddress?: string
  userAgent?: string
  details?: Record<string, unknown>
  result: 'SUCCESS' | 'FAILURE'
}
auditLogger.log(input: AuditLogInput): Promise<void>
```

Convenience wrapper that fixes `result: 'SUCCESS'`:

```ts
auditLogger.logUserAction(userId, action, resource, resourceId?, details?)
```

**Every proposal below uses `auditLogger.log({ ... })` (or `logUserAction`)** as the replacement
for the direct `prisma.auditLog.create(...)` calls, and as the new call for MISSING handlers.
This is the single change that restores the integrity chain. `PENDING HUMAN DETERMINATION`.

### 2.1 Action-string convention (proposal — `PENDING HUMAN DETERMINATION`)

Proposed new writes use `SCREAMING_SNAKE` verbs (`<DOMAIN>_<ENTITY>_<VERB>`). The existing
direct writes use **lowercase** values (`'login'`, `'logout'`, `'journal_proposal_approved'`,
`'journal_proposal_rejected'`, `'journal_proposal_regenerated'`, `'journal_proposal_exported'`).
A human must decide whether to (a) keep the existing lowercase strings for query/report
compatibility, or (b) migrate to the consistent scheme. Both options are shown where relevant.

### 2.2 Common context fields (proposal — `PENDING HUMAN DETERMINATION`)

To reduce boilerplate, a shared helper is recommended (see §7). Until then, each call site
supplies:

```ts
ipAddress: <req>.headers.get('x-forwarded-for') || undefined,
userAgent:  <req>.headers.get('user-agent') || undefined,
```

Routes differ in how the authenticated user is obtained:

- `withAuth`/`withAccountantAuth`/`withAdminAuth` routes → `req.user.id` (and `req.headers`).
- Manual-auth routes (`getAuthUser`/`validateSession`) → `user.id` (and `request.headers`).

## 7. Cross-cutting recommendations (all `PENDING HUMAN DETERMINATION`)

1. **Migrate all direct `prisma.auditLog.create(...)` writes to `auditLogger.log(...)`** (or
   `logUserAction`/`logFailedLogin`/`logAuditRun`/`logFreeeApiCall` where the shape fits). This
   is the single fix that restores the HMAC integrity chain. The 6 Class-A PARTIAL sites (§4.1,
   §4.2) and the 2 out-of-scope `settings/api-keys` sites share this defect.
2. **Add a shared helper** to remove boilerplate and guarantee chain-correct writes, e.g.:
   ```ts
   // proposed: src/lib/audit/route-audit.ts  (file path PENDING HUMAN DETERMINATION)
   export async function logMutation(args: {
     req: { user?: { id: string } } & { headers: Headers }
     action: string; resource: string; resourceId?: string
     details?: Record<string, unknown>
     result?: 'SUCCESS' | 'FAILURE'
   }) {
     await auditLogger.log({
       userId: args.req.user?.id,
       action: args.action,
       resource: args.resource,
       resourceId: args.resourceId,
       ipAddress: args.req.headers.get('x-forwarded-for') || undefined,
       userAgent: args.req.headers.get('user-agent') || undefined,
       details: args.details,
       result: args.result ?? 'SUCCESS',
     })
   }
   ```
   (Exact location/type is out of scope for this read-only task — `PENDING HUMAN DETERMINATION`.)
3. **Log failure paths too.** Several handlers return 4xx/5xx without any audit entry. Decide
   policy on logging `result: 'FAILURE'` (and the failed `LOGIN` / `LOGIN_FAILED` case in §4.1).
4. **Normalize action strings.** Decide lowercase-vs-SCREAMING_SNAKE (§2.1) before implementing,
   to keep log queries stable.
5. **Avoid secrets/PII in `details`.** Freee token values, raw AI responses, and receipt file
   contents must not be logged (§4.9 note). Keep `details` to immutable metadata.
6. **GET-mutation smell.** `GET /api/debt/forecast?action=sync` and (arguably)
   `GET /api/freee/callback` perform state changes via GET. Logging is the minimum; method
   migration is a separate decision (§4.8).
7. **Verify after implementing.** Run `auditLogger.verifyIntegrity()` against a seeded DB to
   confirm no `brokenEntries` remain once direct writes are removed.
